################ advisor build-config get --help
Usage:

Generates the project build configuration.

advisor build-config get [-dh] [-b=<buildTool>]
                         [--build-tool-options=<buildToolOptions>] [-p=<path>]

Description:

Generates the project build configuration: compile time dependencies and
developer tools versions to compile the Java sources of a repository.

The build-configuration is named .advisor/build-config.json. This file is
generated in the build directory of the project (e.g. /target folder for Maven
and /build folder for Gradle). The build-configuration file is required to
generate the upgrade plan of the repository.

Options:

  -b, --build-tool=<buildTool>
                      Selects the build tool used to resolve the project
                        dependencies options: mvnw, mvn, gradlew, gradle
                        (default: mvnw when there are multiple wrappers and mvn
                        when there are no wrappers).
      --build-tool-options=<buildToolOptions>
                      Build arguments to pass to the build tool
  -d, --debug         Prints out debug messages
  -h, --help          Prints the help to understand the command options
  -p, --path=<path>   Selects the root directory of the source code repository
                        (default: current directory)

Examples:

advisor build-config get

Generates the upgrade plan of the repository whose root folder is the current
directory

advisor build-config get --path=/home/user/foo

Generates the upgrade plan of the repository whose root folder is in the
/home/user/foo directory

################ advisor upgrade-plan get --help
Usage:

Prints out the upgrade plan of the source code repository.

advisor upgrade-plan get [-dfh] [--accept-no-alignment] [--build-tools-latest]
                         [--remove-excluded-artifacts] [--squash-all]
                         [-b=<buildTool>]
                         [--build-tool-options=<buildToolOptions>] [-p=<path>]
                         [--squash=<squash>]

Description:

Prints out the upgrade plan of the source code repository. An upgrade plan is
the list of incremental Spring related upgrades that can be performed in
isolation.

Options:

      --accept-no-alignment  Not recommended. Calculates an upgrade plan and
                               upgrades dependencies to their latest versions
                               ignoring miss-alignments.
  -b, --build-tool=<buildTool>
                             Selects the build tool used to resolve the project
                               dependencies options: mvnw, mvn, gradlew, gradle
                               (default: mvnw when there are multiple wrappers
                               and mvn when there are no wrappers).
      --build-tool-options=<buildToolOptions>
                             Build arguments to pass to the build tool
      --build-tools-latest   Adds extra steps to the upgrade plan to maximize
                               the Java version, and update the build tool
                               (Gradle/Maven wrapper), as far as your
                               dependencies allow.
  -d, --debug                Prints out debug messages
  -f, --force                Force execution of full Upgrade Plan, including
                               intermediate dependencies
  -h, --help                 Prints the help to understand the command options
  -p, --path=<path>          Selects the root directory of the source code
                               repository (default: current directory)
      --remove-excluded-artifacts
                             Removes excluded artifacts as part of upgrade plan
      --squash=<squash>      Number of steps of the original Upgrade Plan that
                               will be squashed as the first Upgrade Plan step
      --squash-all           Squashes all the steps of the Upgrade Plan into a
                               single step

Examples:

advisor upgrade-plan get

It prints out the upgrade plan associated to the repository located in the
current directory.

################ advisor upgrade-plan apply --help
Usage:

Incrementally applies an upgrade plan to the source code repository.

advisor upgrade-plan apply [-dfh] [--accept-no-alignment]
                           [--build-tools-latest] [--from-yml] [--push]
                           [--remove-excluded-artifacts] [--squash-all]
                           [--after-upgrade-cmd=<afterUpgradeRunCommand>]
                           [-b=<buildTool>]
                           [--build-tool-jvm-args=<buildToolJvmArgs>]
                           [--build-tool-options=<buildToolOptions>]
                           [-p=<path>] [--scm-host=<scmHost>]
                           [--squash=<squash>]
                           [--exclude-modules=<excludeModules>[,
                           <excludeModules>...]]...
                           [--include-modules=<includeModules>[,
                           <includeModules>...]]...

Description:

Applies the first step of the upgrade plan to the source code repository. If
you want to preview what are the next versions to upgrade your dependencies,
consider using advisor upgrade-plan get.

Options:

      --accept-no-alignment  Not recommended. Calculates an upgrade plan and
                               upgrades dependencies to their latest versions
                               ignoring miss-alignments.
      --after-upgrade-cmd=<afterUpgradeRunCommand>
                             Executes a Maven or Gradle task after applying the
                               upgrade plan
  -b, --build-tool=<buildTool>
                             Selects the build tool used to resolve the project
                               dependencies options: mvnw, mvn, gradlew, gradle
                               (default: mvnw when there are multiple wrappers
                               and mvn when there are no wrappers).
      --build-tool-jvm-args=<buildToolJvmArgs>
                             JVM arguments to pass into the build tool
                               (default: $BUILD_TOOL_JVM_ARGS)
      --build-tool-options=<buildToolOptions>
                             Build arguments to pass to the build tool
      --build-tools-latest   Adds extra steps to the upgrade plan to maximize
                               the Java version, and update the build tool
                               (Gradle/Maven wrapper), as far as your
                               dependencies allow.
  -d, --debug                Prints out debug messages
      --exclude-modules=<excludeModules>[,<excludeModules>...]
                             Comma-separated list of the modules that do not
                               receive the upgrade in a multi-module project.
                               Accepts exact names and wildcards (e.g. test-*).
                               Evaluated after --include-modules
  -f, --force                Force execution of full Upgrade Plan, including
                               intermediate dependencies
      --from-yml             Enables the upgrade plan based on the contents of
                               the .spring-app-advisor.yml file in the selected
                               path.
  -h, --help                 Prints the help to understand the command options
      --include-modules=<includeModules>[,<includeModules>...]
                             Comma-separated list of the modules that receive
                               the upgrade in a multi-module project. Accepts
                               exact names and wildcards (e.g. core,api-*).
                               Every module is selected when this option is
                               absent. A version managed in the root build file
                               changes only when the root module is selected
  -p, --path=<path>          Selects the root directory of the source code
                               repository (default: current directory)
      --push                 Generates a pull request with the code upgrades.
                               The environment variable GIT_TOKEN_FOR_PRS is
                               mandatory. It should contain the value of a
                               token with permissions to create pull requests
                               in the repository
      --remove-excluded-artifacts
                             Removes excluded artifacts as part of upgrade plan
      --scm-host=<scmHost>   Trusted hostname for self-hosted GitLab or GitHub
                               instances. Required when using --push with any
                               host other than github.com or gitlab.com. (e.g.
                               gitlab.mycompany.com). (default:
                               $ADVISOR_SCM_HOST)
      --squash=<squash>      Number of steps of the original Upgrade Plan that
                               will be squashed as the first Upgrade Plan step
      --squash-all           Squashes all the steps of the Upgrade Plan into a
                               single step

Examples:

advisor upgrade-plan apply

Upgrades the repository that is in the current directory

advisor upgrade-plan apply --push

Upgrades the repository and creates a pull request with the changes

advisor upgrade-plan apply --push --from-yml

Upgrades the repository and creates a pull request with the changes if
developers have explicitly enabled automatic updates

advisor upgrade-plan apply --build-tool-jvm-args=-Xmx2048M

Upgrades the repository in the current directory. The upgrade will use 2Gb of
memory to parse all the sources into memory.

################ advisor mapping search --help
Usage:

Searches for projects by slug prefix.

advisor mapping search [-h] [--prefix=<prefix>] [--slug=<slug>]

Description:

Searches all loaded mapping sources for projects whose slug starts with the
given prefix. Displays an interactive, paginated list of matching project
slugs. When a result is selected, optionally saves its mapping JSON to .
advisor/mappings/<slug>.json. Provide --slug to download a known mapping
directly, skipping the interactive selection.

Options:

  -h, --help              Prints the help to understand the command options
      --prefix=<prefix>   Prefix to match against project slugs
                            (case-insensitive). Required for the interactive
                            search when --slug is not given.
      --slug=<slug>       Exact project slug (case-sensitive) to download
                            directly, without the interactive selection step.

Examples:

advisor mapping search --prefix spring-boot

Searches for all projects whose slug starts with "spring-boot".

advisor mapping search --prefix s

Searches for all projects whose slug starts with "s". If more than 20 results
are found, type a narrower prefix to filter further.

advisor mapping search --slug spring-boot

Downloads the mapping for the exact slug "spring-boot" directly, without the
interactive selection.



################ advisor mapping update --help
Usage:

Updates existing mapping files with newly released library versions.

advisor mapping update [-dh]

Description:

Scans the path for existing mapping files and appends any newly released minor
versions of their libraries, following the same logic as 'mapping create'.
Previously existing entries are left unchanged.



Options:

  -d, --debug   Prints out debug messages
  -h, --help    Prints the help to understand the command options

Examples:

advisor mapping update

Updates every mapping file found under the current directory.
